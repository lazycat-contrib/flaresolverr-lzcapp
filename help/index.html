🛡️ FlareSolverr

使用指南 - API 参考

📋 简介

FlareSolverr 是一个代理服务器，用于绕过 Cloudflare 和 DDoS-GUARD 保护。

工作原理

FlareSolverr 启动一个代理服务器，在空闲状态下使用少量资源等待用户请求。当请求到达时，它使用 Selenium 和 undetected-chromedriver 创建一个浏览器（Chrome）。它使用用户参数打开 URL 并等待 Cloudflare 挑战被解决（或超时）。HTML 代码和 Cookie 会发送回用户，这些 Cookie 可用于使用其他 HTTP 客户端绕过 Cloudflare。

⚠️ 内存消耗警告
Web 浏览器消耗大量内存。如果在内存较少的机器上运行 FlareSolverr，不要同时发出太多请求。每个请求都会启动一个新的浏览器。
💡 会话模式
也可以使用永久会话。但是，如果使用会话，应确保在使用完毕后尽快关闭它们。

使用场景

  • 爬虫绕过保护：当爬虫遇到 Cloudflare 或 DDoS-GUARD 保护时，通过 FlareSolverr 获取有效的 Cookie 和 HTML
  • 自动化测试：需要访问受保护网站的自动化脚本
  • 数据采集：从受保护的网站采集数据
  • 会话管理：需要持久化会话避免重复验证

🔧 命令

+ sessions.create
这将启动一个新的浏览器实例，该实例将保留 Cookie，直到您使用 sessions.destroy 销毁它。 这非常方便，因此您不必不断解决挑战，也不需要不断发送 Cookie 给浏览器使用。 这还加快了请求速度，因为不必为每个请求启动新的浏览器实例。
参数 说明 session 可选。要分配给实例的会话 ID。如果未设置，将分配随机 UUID proxy 可选，默认禁用。例如："proxy": {"url": "http://127.0.0.1:8888"}。必须在 URL 中包含代理架构：http://, socks4:// 或 socks5://。支持授权（用户名/密码）。例如："proxy": {"url": "http://127.0.0.1:8888", "username": "testuser", "password": "testpass"}
+ sessions.list
返回所有活动会话的列表。主要用于调试，如果您好奇有多少会话正在运行。 您应确保在使用完毕后正确关闭每个会话，因为太多会话可能会减慢计算机速度。
{ "sessions": ["session_id_1", "session_id_2", "session_id_3..."] }
+ sessions.destroy
这将正确关闭浏览器实例并删除所有关联的文件以释放资源。 当不再需要使用会话时，应确保关闭它。
参数 说明 session 要销毁的会话 ID
+ request.get
参数 说明 url 必需 session 可选。从现有浏览器实例发送请求。如果未发送，将创建临时实例，请求完成后立即销毁 session_ttl_minutes 可选。FlareSolverr 将根据提供的 TTL（分钟）自动轮换过期的会话 maxTimeout 可选，默认值 60000。解决挑战的最大超时时间（毫秒） cookies 可选。将被 headless 浏览器使用。例如："cookies": [{"name": "cookie1", "value": "value1"}, {"name": "cookie2", "value": "value2"}] returnOnlyCookies 可选，默认 false。仅返回 Cookie。响应数据、标头和其他部分将被移除 returnScreenshot 可选，默认 false。捕获最终渲染页面的屏幕截图（在所有挑战和等待完成后）。屏幕截图作为 Base64 编码的 PNG 字符串返回在响应的 screenshot 字段中 proxy 可选，默认禁用。例如："proxy": {"url": "http://127.0.0.1:8888"}。必须在 URL 中包含代理架构：http://, socks4:// 或 socks5://。不支持授权（用户名/密码）。(当设置了 session 参数时，proxy 会被忽略；可以在 sessions.create 中设置会话特定的代理) waitInSeconds 可选，默认无。解决挑战后等待的秒数，然后再返回结果。对于允许加载动态内容很有用 disableMedia 可选，默认 false。为 true 时，FlareSolverr 将阻止加载媒体资源（图像、CSS 和字体）以加快导航速度 tabs_till_verify 可选，默认无。需要按 Tab 键的次数以到达 turnstile captcha 进行验证。验证后，结果将存储在 solution 下的 turnstile_token 中
⚠️ 警告： 如果您想在脚本中使用 Cloudflare clearance cookie，请确保也使用 FlareSolverr 的 User-Agent。如果它们不匹配，您将看到挑战。
+ request.post
这与 request.get 类似，但增加了 postData 参数。 注意：tabs_till_verify 目前仅支持 GET 请求，并且需要一个额外的参数。
参数 说明 postData 必须是 application/x-www-form-urlencoded 格式的字符串。例如：a=b&c=d
